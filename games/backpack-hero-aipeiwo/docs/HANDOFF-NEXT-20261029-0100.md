## 1. 这一班改了什么（都已在真机验过）

1. **`place_item` 落点**：新增 `via=start`（默认）。顺序：
   `StartDrag()` → `transform.position = target` → `SetField(startPosition, 位置)` →
   `SetField(startRotation, 当前朝向)` → 反射 `EndDrag()`。
   - 连放两件时先 `isStoppingDrag=false`，否则 `StartDrag()` 直接 return。
   - `rot=identity` 可强制转正；默认保持当前朝向（候选格形状是按它算的）。
2. **`PredictCells()`**：不能直接 `GetGridPositionsAtPosition(target)`——物品离目标远时
   会多算一格（3 格剑预测成 4 格，落到 `-1,2` 出界）。改成先把 transform 挪到 target
   再算、算完挪回，预测 = 落点。
3. **验收门**：`place_item` 的 ack 只在 `Actions.ItemInBag(uid)` 为真时 `ok=true`
   （`cells ⊆ GridSquare.allGrids` 且 `parent == Grid Parent`）。
   **不要再用 `items_in_grid` 验收**：`AddToGrid` 在占格判定之前就置 `inGrid=true`。
4. **扩容**：`unlock_spaces n`（点真实 `GridExtension.Click`）、`grant_spaces n`
   （**测试钩子**，只加配额）、`clear_spaces`（清余额）。
   `finish_level_up via=spaces` 之前的 `ChangeSpaces(+numberToUnlock)` 会把配额翻倍
   （实测刷到 256），已改成和 `select` 一样走 `Select()`。
5. **`Snapshot.GridSquares`**：扩容只改格子数，不加这个字段动作会被判 changed=false。
6. **`diag_place`**：只读诊断，逐格打印「放这里会占哪些 cell / 是否在包内 / 是否全空」，
   加 `diag_levelup` 时可以参考它的写法。
7. **`move_item` / `rotate_item` / `drop_item`（v8.14）**：都先 `StartDrag()`（`Rotate()`
   在 `inGrid=true` 时直接 return；`RemoveFromGrid` 会腾出旧格子）。move/rotate 在
   `EndDrag` 之前验证 footprint，不合法就回原位并抛错；drop 把 transform 放到
   `maxX+6, minY-2` 再纠正 `inGrid=false / objsInGrid-1`，物品变 loose。
8. **`ResolveGridObject()`**：`Item2.gridObject` 可能是 null（drop 之后常见），
   没有它形状算不出来 → 老逻辑会盲放第一个空格、**叠到别的物品上**。
   现在必要时调 `ItemMovement.GetGridObject()` 补建，补不出来直接报错。
9. **`RefreshOccupancy()`**：按所有 `inGrid` 物品的 `gridPositions` 重算
   `GridSquare.containsItem`；place/move/rotate/drop 之后都调。
10. **`Snapshot.BagSig`**：`uid:cells` 排序串。move/rotate 不改物品数，只靠它判 changed。
11. **错误立即回执**：`Actions.Execute` 抛错时 `BridgeMod` 直接 `FinishPending`，
    失败 ~100ms 返回（以前要等满 10 秒阶段门）。

## 2. 已确认（别重查）

- `EndDrag`：`transform.position = startPosition; transform.rotation = startRotation;
  AddToGrid(false)`；`StartDragWithoutChecks` 末尾才写 startPosition/startRotation。
- `AddToGrid` 自己会把 `parentInventoryGrid` 设成**格子父节点**（`Grid Parent`）；
  `Items` 是包外容器。
- `GetGridPositionsAtPosition(pos)` 只在「物品已在 pos 附近」时准；远距离预测会偏一格。
- `ChangeSpaces(n)` = `numberToUnlock += n`（加配额），不是加格子；
  `Select()` = `ChangeSpaces(-1)` + `SetupSpaces()`；
  `GridExtension.Click()` 才是「把这格并进背包」。
- 新开局 `numberToUnlock = spacesSaved = 0`（`<LevelUp>d__39` 里 rewardType 0/2 都这么写），
  界面显示「选择 0 个格子」，点 extension 没反应 → 才需要 `grant_spaces`。
- **`CanLevelUp() = (xp 够 || spacesSaved > 0) && !levelingUp`**：不把余额清零，
  升级界面会无限重开，而且每次 `LevelUpButton()` 都会 `IncrementLevel()` 刷高等级。
- 新格子是在 **EndLevelUp 时**才真正并入（ack 的 `delta.grid_squares` 在 finish 那步）。
- `GridSquare.containsItem` 会滞后：用 `RefreshOccupancy()` 以 `gridPositions` 为准重算。
- `ItemMovement.Rotate(angle)` 在 `inGrid == true` 时第一行就 return；且拖拽中它绕鼠标转，
  所以自动化里直接改 `transform.eulerAngles.z`，不要调它。
- `RemoveFromGrid()`：清 `gridPositions`、`parentInventoryGrid=null`、`inGrid/inPouch=false`、
  `objsInGrid-1`。

## 3. 下一步（按优先级）

### 3.1 把 move/rotate/drop 接进策略（最有用）

现在三个动作只有桥接层能做，`legal` 里没有、`loop.py` 也不会用。建议：

- `MapProbe.WriteLegal` 在「背包有空位但放不下当前战利品」或「free==0 且有 loose」时，
  给 `move_item` / `drop_item` 候选（带 uid + 建议 cell）。
- `loop.py` 加 `--make-room N`：`place_item` 返回 `no fitting cell` 时，挑一件
  价值最低的背包物品 `drop_item`（价值可用账本均值，或 `costs` 里的 gold），再重试放置。
- 放置前先算「战利品需要几格」，只有腾出**连续**空间才有意义——现在只能靠试。

### 3.2 swap（两件物品互换）

move 只接受「目标整块空着，或只压到自己的旧格子」。真正整理背包需要 swap：
把 A 拖起 → 把 B 移到 A 的旧格 → 再把 A 放到 B 的旧格。两个 move_item 就能拼，
但要处理「B 的旧格也算空」的中间态。

### 3.3 按朝向搜索落点

`rotate_item` 只按当前形状挑落点；「转 90° 才放得下」的情况需要
4 朝向 × 所有空格的小搜索（`PredictCells` 已经能算每个朝向的 footprint）。

### 3.4 扩容正常化

`grant_spaces` 是测试钩子。正常升级里 `spacesSaved` 永远是 0（见 §2），需要确认这是
游戏 bug 还是我们漏了某个入口（例如 rewardType 2 的分支里
`numberToUnlock = Min(rewardValue, extensions)` 被下一行 `= spacesSaved` 覆盖）。
如果能找到正常来源，`--unlock-spaces` 就可以去掉 `--grant-spaces`。

### 3.5 `containsItem` 滞后

`free_squares` 偶尔少报 1（13 格那局 `free=3` 时实际有 4 个空格）。
v8.14 起 `RefreshOccupancy()` 会在 place/move/rotate/drop 之后重算，但**别的地方**
（消耗品用掉、战斗结算）仍可能留下旧标记；看到 `free` 可疑就先调一次。

### 3.6 地图视觉

`close_map` 能把 `viewing_top` 置 0，但地图那层动画不一定收起，背包会被盖住
（截图验收时踩到）。要真正关掉得走地图按钮的 onClick / Animator，别只置位。
