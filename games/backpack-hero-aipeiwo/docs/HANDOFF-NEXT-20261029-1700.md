## 2. IL 事实（别重查，`Ildump` 逐方法核对过）

```
DungeonEvent.Play()      open 属性当幂等标记；先 AddEventProperty(open,0) 再生成
SimpleClickItem.Start()  Play 之后**下一帧**才跑：GetItems() 把事件下挂的 Item2 孩子
                         SetActive(true)（且不还原），摆到祭坛前
SimpleClickItem.Click()  IsFinished/travelling/isOpen 三道门 → FinishEvent + TakeAction 协程 + isOpen=true
TakeAction()             0=HP 1=EXP 2=Gold 3=地牢属性 4=item(**什么都不做**) 5=meta 6=生成物品
```

推论：`item` 类事件的东西是 **Start() 摆出来的**，`Click()` 只收尾。所以
「东西变 loose」发生在 Play 之后那一帧，**同一帧量 items_loose 永远是 0**。

## 8. 扩容的证据链（怕以后又走回头路）

```
Xref LevelUpManager spacesSaved
  -> 写入点 3 个：EndLevelUp（存余额）、Player.IncrementLevel（**唯一加**）、SaveManager.Load
Player.IncrementLevel():
  spacesSaved += levelUps[level].rewards[0].rewardValue
diag_levelups（Purse）: 16 级，每级 rewards[0] = {type:0(加格子), value:4/4/3/3/…/1}
真机: level_up -> spaces_saved 0→4, number_to_unlock 4
      unlock_spaces ×4 -> number_to_unlock 4→0
      finish_level_up via=end -> grid_squares +4  (9 → 13)
loop 自动: grid 13 → 17
```

**别再用 `grant_spaces` / 直接改 `numberToUnlock` 验扩容**：`ChangeSpaces` 是累加语义，
会把配额刷爆并写回 `spacesSaved`，把之后所有判断都带偏（E17）。
