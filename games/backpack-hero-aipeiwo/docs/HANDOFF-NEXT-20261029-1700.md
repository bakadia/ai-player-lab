## 0. 30 秒

**上一班说「`play_event` 的 `Click()` 收不进包」，这个结论是错的。**

- `SimpleClickItem.Click()` 在真机上**是生效的**：`+5 gold`、`+5 hp` 各验证一次
  （`gold 0→5`、`hp 36→40`）。
- 当时点的那两个 SCI 是 **`QuickBoost HP / Gold`** 变体，`effects` 里只有
  `type=0/2`，`event_items` 是空的——**它本来就不往地上掉东西**，`loose 0→0` 是正常。
- 「`Play()` 会叠对象」也不是游戏的锅：`Play()` 开头就 `if (GetEventProperty(open)) return;`
  **本来就幂等**；v8.16 的 `play_event` 每次先 `RemoveEventProperty(open)` 才让它重复生成。
  v8.17 删掉那一行，重复发会得到 `play_skip="already_open"`、对象数不变（真机验证过）。

## 1. 这一班改了什么（v8.17）

1. ✅ `play_event` 加 `play` / `click` 两个开关；Play 不再清 `open`；只点 `isOpen=false` 的 SCI。
2. ✅ `play_event` 的 diag 扩成「能看清一切」：`played / play_skip / open_after /
   finished_after / click_items_before / click_error`，外加
   `event_items[]`（事件下挂的 Item2）和 `click_items[]`（SCI 的 isOpen、激活链、
   effects 的 type/num、assigned item 的 display/active/in_grid）。
3. ✅ 新只读动作 **`diag_items`**：所有 `Item2` 分 `active` / `inactive` 两段列
   （`FindObjectsOfType` 看不见未激活的；用 `Resources.FindObjectsOfTypeAll` + `scene.IsValid()`）。
   用来分辨「生成了但没激活」vs「根本没生成」——这两者在 `items_loose` 上长得一样。
4. ✅ `BridgeMod`：`play_event` 的 ack 门只在事件真有 `type=4(item)` 时才等 loot
   （`Actions.PlayEventExpectsLoot`）。否则 QuickBoost 会白等 15 秒并回 `ok=false`。
5. ✅ 新工具 `tools/bph_verify_pickup.py`：两步验收 + effect 解释 + 变化表 + 证据 JSON。

## 2. IL 事实（别重查，`Ildump` 逐方法核对过）

```
DungeonEvent.Play()      open 属性当幂等标记；先 AddEventProperty(open,0) 再生成
SimpleClickItem.Start()  Play 之后**下一帧**才跑：GetItems() 把事件下挂的 Item2 孩子
                         SetActive(true)（且不还原），摆到祭坛前
SimpleClickItem.Click()  IsFinished/travelling/isOpen 三道门 → FinishEvent + TakeAction 协程 + isOpen=true
TakeAction()             0=HP 1=EXP 2=Gold 3=地牢属性 4=item(**什么都不做**) 5=meta 6=生成物品
```

推论：`item` 类事件的东西是 **Start() 摆出来的**，`Click()` 只收尾。所以
「东西变 loose」发生在 Play 之后那一帧，**同一帧量 items_loose 永远是 0**。
